# Weektris — инструкция по запуску

Weektris — твой личный трекер загрузки по неделям. Раньше он жил как Claude Artifact,
теперь это самостоятельный сайт на GitHub Pages: календарь читается напрямую из
Google, а общие данные (проекты, часы, история) хранятся в файле `data.json` внутри
этого репозитория.

**Как это устроено:**
- Только ты подключаешь Google Calendar и вносишь правки — для этого нужен
  GitHub-токен, который ты один раз вставишь в браузер.
- Коллеги и руководитель просто открывают ссылку и видят последний сохранённый
  снимок данных — никаких аккаунтов, токенов и доступа к твоему календарю им не нужно.
- Когда ты синкаешь календарь или редактируешь часы, страница сохраняет новую
  версию `data.json` прямо в репозиторий, и GitHub Pages обновляет сайт
  автоматически (обычно 30–60 секунд).

Раз у тебя уже есть корпоративный GitHub-аккаунт — лучше создать репозиторий именно
в организации inDrive и сделать его **приватным**. Тогда сайт будет доступен только
тем, у кого есть доступ к репозиторию (это настраивается в организации), а не всем
в интернете. Если по какой-то причине корпоративный GitHub не подойдёт (например,
GitHub Pages для приватных репозиториев доступен не на всех тарифах), можно
использовать личный аккаунт — но тогда репозиторий должен быть публичным, и
ссылку сможет открыть кто угодно, у кого она есть.

---

## Шаг 1. Создать репозиторий и залить файлы

1. Зайди на github.com под корпоративным аккаунтом, открой организацию inDrive
   (или ту, в которой создан твой аккаунт).
2. Создай новый репозиторий, например `weektris`. Если доступно — выбери
   **Private**.
3. Залей туда все файлы из этой папки: `index.html`, `config.js`, `data.json`,
   `.nojekyll`, `README.md`. Можно просто перетащить их в репозиторий через
   веб-интерфейс GitHub (кнопка "Add file → Upload files").

## Шаг 2. Включить GitHub Pages

1. В репозитории: **Settings → Pages**.
2. В разделе "Build and deployment" выбери источник **Deploy from a branch**,
   ветку **main**, папку **/ (root)**. Сохрани.
3. Через минуту-две GitHub покажет ссылку вида
   `https://<org-или-username>.github.io/<repo>/` — это и есть адрес твоего Weektris.
   (Если репозиторий приватный и Pages для приватных репо недоступен на вашем
   тарифе GitHub — об этом будет явно написано в интерфейсе; тогда см. примечание
   про личный аккаунт выше.)

## Шаг 3. Настроить доступ к Google Calendar (OAuth)

Нужно один раз создать "клиента" в Google Cloud, который разрешит странице читать
твой календарь (только на чтение, без права что-либо менять).

1. Открой [Google Cloud Console](https://console.cloud.google.com/) под своим
   рабочим Google-аккаунтом.
2. Создай новый проект (или используй существующий).
3. **APIs & Services → Library** — найди **Google Calendar API** и нажми **Enable**.
4. **APIs & Services → OAuth consent screen** — заполни минимально необходимое
   (имя приложения — например "Weektris", свою почту). Тип пользователя —
   **Internal**, если доступен для inDrive-организации в Google Workspace (тогда
   подключаться сможешь только ты и коллеги внутри организации); если **Internal**
   недоступен — выбери **External** и добавь себя в тестовые пользователи (test users).
5. **APIs & Services → Credentials → Create Credentials → OAuth client ID**.
   - Тип приложения: **Web application**.
   - **Authorized JavaScript origins** — добавь адрес твоего сайта из Шага 2,
     БЕЗ пути в конце, например: `https://your-org.github.io`.
   - Создай — появится **Client ID** вида
     `123456789-abc...apps.googleusercontent.com`. Скопируй его.

## Шаг 4. Вписать настройки в config.js

Открой `config.js` в репозитории (можно прямо на github.com, кнопка карандаша —
"Edit") и впиши:

```js
window.WEEKTRIS_CONFIG = {
  GOOGLE_CLIENT_ID: "тот самый Client ID из Шага 3",
  GITHUB_OWNER: "название организации или твой username на GitHub",
  GITHUB_REPO: "weektris",       // имя репозитория, если назвала иначе — поменяй
  GITHUB_BRANCH: "main",
  DATA_PATH: "data.json"
};
```

Сохрани (commit). Через минуту сайт пересоберётся с новыми настройками.

## Шаг 5. Создать GitHub-токен для сохранения данных

Это токен, который позволяет ТОЛЬКО ТЕБЕ (с твоего устройства) сохранять новые
данные в `data.json`. Он никогда не попадает на сайт и не виден коллегам —
хранится только в твоём браузере.

1. **GitHub → Settings (аккаунта, не репозитория) → Developer settings →
   Personal access tokens → Fine-grained tokens → Generate new token**.
2. Repository access: **Only select repositories** → выбери свой `weektris`.
3. Permissions → **Repository permissions → Contents: Read and write**.
   Больше ничего не давай — этого достаточно.
4. Сгенерируй и скопируй токен (он показывается один раз).

## Шаг 6. Первый запуск

1. Открой ссылку сайта из Шага 2.
2. Нажми **⚙ settings** в правом верхнем углу.
3. Вставь токен из Шага 5 в поле и нажми **Enable**.
4. Появится кнопка **connect calendar** — нажми её, войди под рабочим Google-
   аккаунтом и разреши доступ на чтение календаря.
5. Данные за прошлую и текущую неделю подтянутся, страница сама сохранит их в
   `data.json` в репозитории.

После этого раз в неделю (или когда удобно) просто открывай сайт и жми
**resync calendar**, чтобы обновить цифры по звонкам, плюс вноси часы по проектам
как раньше — Enter сохраняет.

## Как этим пользуются коллеги и руководитель

Просто отправь им ссылку на сайт (из Шага 2). Кнопки настроек, подключения
календаря и редактирования часов у них не появятся — они увидят твои актуальные
цифры в режиме только для чтения. Если репозиторий приватный, доступ к сайту будет
только у тех, кто состоит в организации / имеет доступ к репозиторию — уточни у ИТ,
как именно это ограничение работает на вашем тарифе GitHub.

## Если что-то не так

- **"Couldn't load data.json"** — проверь `GITHUB_OWNER`/`GITHUB_REPO`/`GITHUB_BRANCH`
  в `config.js` и что файл `data.json` реально лежит в репозитории.
- **Google Calendar не подключается** — проверь, что в Шаге 3 в Authorized
  JavaScript origins указан ТОЧНО тот адрес, с которого открыт сайт (без `/` в конце).
- **"GitHub write failed"** — скорее всего токен истёк или у него не хватает прав
  (Contents: Read and write на нужном репозитории). Пересоздай токен через Шаг 5.
